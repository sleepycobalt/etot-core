# Notes — etot-core

Dated lines: decisions, surprises, failures, numbers. Newest last.

- 2026-09-10 — 0.1.0 extracted from Motif and published (Motif `docs/part3-notes.md`, 2026-09-10). Source in this repo verified byte-identical to the PyPI 0.1.0 wheel before any 0.2.0 change (sha256 7bb6858c…c1aae6c44). 0.1.0 shipped with no tests of its own.
- 2026-09-10 — 0.2.0: two Motif assumptions removed, both found by the second consumer, Moiré, and recorded in `moire/docs/case-study-notes.md` (2026-09-10). Fixed here in core rather than worked around in the tool, per Moiré's ruling 16: no workarounds in the shared engine, ever.
  1. `load_config` required an Anthropic key unconditionally, so a tool whose deterministic path never calls a model could not load its config without one (Moiré's B′ read its YAML privately to get past it). Added keyword-only `require_key: bool = True`. The default is Motif's behaviour exactly; `False` skips only the key check — `.env` is still loaded, the same defaults applied.
  2. `RunLogger.snapshot_corpus` assumed Motif's transcript shape: every manifest entry had `words`, and every entry's files were `<name>.txt` + `<name>.jsonl` (Moiré wrote an outline `.txt` and an outline word count only to satisfy it). Minimal generalisation: an entry may declare `"files": [...]` (plain file names, validated before anything is written); without it the default is unchanged; `words` is recorded only when every selected entry has it. Inputs that worked in 0.1.0 produce byte-identical snapshots and meta; only inputs that raised in 0.1.0 now succeed.
- 2026-09-10 — Left out of 0.2.0 on purpose, recommended as its own release: the remaining Motif vocabulary in the snapshot API — the meta key `corpus.transcripts` and the method name `snapshot_corpus`. Motif reads `meta["corpus"]["transcripts"]` (`synth/board.py:106`, `tests/test_engine.py:98, 280`), so renaming is a breaking change that needs an alias and a Motif release, not a patch to carry here.

- 2026-09-10 — Surprise worth keeping: Motif's 54 offline tests run from a scratch venv failed 28 with `ANTHROPIC_API_KEY not set` — on 0.1.0 and 0.2.0 alike. `load_dotenv()` searches upward from the installed `etot_core`, which reaches `motif/.env` only when the venv lives inside the Motif checkout. A test suite whose pass count depends on where the venv sits is a finding about the environment, and a comparison is only valid with the environment held fixed.

- 2026-09-11 — 0.3.0: a third Motif assumption, found by the second consumer while building its loop, and the first that would have corrupted a result rather than refusing to run. `run_loop` detected no progress by comparing `frozenset((f.get("insight_id"), f.get("rule")) for f in failures)` — Motif's vocabulary hard-coded. Moiré's failures are named by finding id, so every one keyed as `(None, rule)`: an objection to finding F-001 under wrong_binding and a different objection to F-007 under wrong_binding compared equal, and the loop would have stopped `no_progress` while progress was being made — silently, with no error, and with the stop reason recorded as a research measure. Filling `insight_id` with finding ids to satisfy it is the dummy value Moiré's ruling 16 forbids (moire docs/brief.md). Fix: keyword-only `failure_key: Callable[[dict], Hashable] | None = None`; the default is Motif's key exactly. Also fixed in the README, because it documents the function this release changes: the `run_loop(state, …)` example had raised TypeError since 0.1.0 (`state` is keyword-only); it now reads `state={}` and was run against the code.
